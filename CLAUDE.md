# Mirrorfold

A first-person fly-through of endless fractal worlds in the browser: WebGL 1 raymarching, a MilkDrop-style feedback and filter chain, music reactivity, and a templated autopilot ("Journey"). The app is `index.html` (markup), `css/app.css` and ES modules in `js/`. No build step, no dependencies.

Read `docs/ARCHITECTURE.md` before changing anything substantial. It covers the render pipeline, the math of every world, the audio analysis, the journey engine, known weaknesses and a suggested refactor.

## Commands

```
node tools/unit.mjs                     # pure-logic tests (change detector, weighted picker, head-turn math, pack cleaners)
node tools/pack.mjs                     # check every pack in packs/ with the app's own cleaners, and that packs/index.json is up to date
node tools/gallery.mjs                  # write packs/index.json from the pack files (never edit it by hand)
python3 tools/check.py                  # headless smoke test: all shaders compile, no script or GL errors
python3 tools/probe.py                  # every world's GLSL map against its JavaScript de, through the distance probe
python3 tools/render.py --world julia -o out.png          # screenshot one world
python3 tools/render.py --all -o sheet.jpg                # contact sheet of every world
python3 tools/render.py --world temple --js "setLook(2)" -o neon.png
python3 tools/render.py --world sponge --js "setLand(2);setLandFx(1)" -o land.png   # the land over a world; setLand(1) is the land alone; setLandKind(1) canyon, (2) strange planet, (3) steel ball, (4) city
python3 tools/render.py --world sponge --size 852x393 --js "setStereo(true)" -o vr.png   # VR viewer picture
python3 tools/thumbs.py                 # the choosers' small pictures in thumbs/; "thumbs.py world-foam" makes one, "thumbs.py filter" one kind
python3 tools/voice.py                  # the lessons' voice in voice/, from the words in lang/ (needs kokoro, soundfile, ffmpeg; here: .venv-voice/bin/python tools/voice.py)
python3 tools/stereo.py clean.png effect.png   # how well the two eyes' halves of VR viewer pictures agree (needs numpy)
```

The Python tools need `google-chrome` or `chromium` on PATH (they run it headless with software WebGL). `--all` also needs Pillow. To view the app, serve the folder with `python3 -m http.server` (modules do not load from `file://`).

## Rules that are easy to break

- **Every world has its distance estimator twice**: GLSL in `glsl` (`map`) and JavaScript in `de`. They must match. JavaScript uses it for flight speed, autopilot steering and orb placement.
- **The land has its height twice too**: the noise sum in `terrL`/`terrM` (in `LAND_T`) and in `landH`, both reading the table `LTAB`, and each landscape's `shape` in its GLSL and in its `LK` entry. They must match. A landscape's free-standing shapes are twice too: `extra` in GLSL and in JavaScript. So are the city's blocks (`block` in `citySrc`, `cityBlock` in JavaScript). `shapeU` must never be below `shape` over a range of 0.047 either side. Its layers use the whole-number matrix `[2 -1; 1 2]` so that it repeats exactly every `LPERIOD`; do not replace it with an arbitrary rotation.
- **The land shader measures from the camera.** World positions go in through `uCi`/`uCf` and the like, worked out in doubles in `landPass`. Do not add a pattern finer than about 1/50 unit that is computed from `uPos` in the shader: it will shake.
- **Every built-in world, palette, motion, filter, overlay, mirror setting, FX setting, surface and landscape has a picture in `thumbs/`**, which its chooser shows (`js/picker.js`). After adding or renaming one, or changing how it looks, run `python3 tools/thumbs.py` for it; `tools/unit.mjs` fails if a picture is missing. A picture's address is made only by `thumbName` from a built-in's own name: never from anything in a pack.
- **The lessons' words live only in `lang/<language>.json`**, a flat file of names and text; `js/learn.js` and `js/figures.js` show them through `t()` and `textContent`, never as HTML. Do not put lesson text in the markup or the scripts. The voice is made from those same words: after changing any of a step's four texts run `tools/voice.py`, or `tools/unit.mjs` fails. Write lesson text so that it reads aloud well: words, not symbols; the symbols go in the numbers under the drawing (`read`).
- **The lessons explain in plain words first and give the mathematical name last** (the `.name` text). Keep that order.
- **A lesson step's name is unique across all tracks** (the drawings are looked up by it), and each track's `chapters` must add up to its steps; `tools/unit.mjs` checks both. The lessons' drawing files read the app's palettes, motions and worlds only inside functions, never at the top level.
- **A lesson step carries one idea.** If a step needs two new ideas, make two steps. Every value a step's text asks the reader to find must be in that drawing's `keys`, so that it is sticky and has a button. Never draw a point's hops over the grid of squares: use `inset`. The numbers under a drawing show the sum that gives each answer, not the answer alone, and a drawing that repeats a rule has `walk`, so its hops can be followed one at a time.
- **A world that picks something per cell must do it with whole numbers**, as Tangle does (`mo`, sums below 2^24), so that the chip and JavaScript choose alike. A `fract(sin())` hash is fine only where JavaScript has no copy (the cloud worlds).
- **Every surface pattern must repeat with the world.** `woodAt`, the fibres and marble in `js/shaders.js` are built only from sines and cosines of whole multiples of the angles `q`, which go round a whole number of times in the world's period (`uPer`). The surfaces made of blocks (dots, tiles, wire, cells) take a whole number of blocks to the period from `sfN` and count a block round the period before taking its chance number. Do not add ordinary noise, a multiplier that is not a whole number, or a block size not from `sfN`: the pattern would jump when the camera is wrapped. A surface takes the sound and the clock only through the scene shader's uniforms, so that Hold still stops it, and a new one needs its picture in `thumbs/`.
- **The worlds made of one shape repeated (`packs: true`) give only their shape** (`shape` in GLSL, a function named `SHAPE`; `sde` in JavaScript; `rad`, the ball that holds it at every morph; `grid`; `mix`, two other such worlds). `packSrc` and `packDe` in `js/worlds.js` build `map` and `de` from them, and `pkP` and `pkD` in `js/packing.js` place the copies, with a shader half and a JavaScript half like a world. Scattered, nested and sponge work from boxes: what a box holds must be chosen from whole numbers counted round the period, with every product under 2^22, so that the two halves choose alike, and nothing in a box may come nearer its walls than `PK_GAP * P`: the distance is held to "the wall, and the gap" on the strength of that. There, in open space, JavaScript's answer is deliberately larger than the shader's (it looks in all the boxes round about, so that flight does not take a box's wall for a surface); `setPkPlain(true)` makes it the shader's, and `tools/probe.py` compares them that way in every packing. Helix, shells and descent work from balls: the copy whose middle is nearest, held to the nearest of the other balls, and the two halves answer alike. A new packing must keep `tools/unit.mjs`'s test that a step as long as the shader's distance never ends inside a shape. The packing changes those worlds' period, and the pulse and the shapes change every copy, so anything that keeps a place across a change of any of them is wrong: `setPacking`, `setPulse` and `setMix` put the camera in open space again.
- **Inside a `shape`, `uM` is the copy's own morph** (`pkU`, by a `#define` in `packSrc`), and `sde` is handed the same number: with Pulse wave each copy is some seconds behind the morph's clock (`pkMo`, from `pkTick`). Do not read the morph any other way in a shape.
- **The descent is not periodic: it is the same three times larger.** `move` multiplies the camera's place by 3 or 1/3 to keep it between `DP_IN` and three times that from the centre (`pkJump`; `fr.jump` says by how much). Whatever has a place in the world must be moved with it in the same frame (the orb, the sprites and the thrown light are; a doorway is not allowed there). Everything in the scene shader that is a length must be multiplied by `SC` (the fog, the reach, the first step), and a surface's pattern must be worked out from `SP`, the place within the copy, or the move shows. A flight is not recorded there.
- **A world's program is made for what is chosen**: with the chrome surface in it or not, with three shapes or one (`fragSource`, from `chrome` and `pkMix`). `setProgSet` in `js/programs.js` keeps one set of programs for each way, and only `progSync` in `js/choose.js` changes the set. Anything else that changes what `fragSource` returns must be part of the set's name.
- **Every world's field must be exactly periodic** with its `period`. The camera position is wrapped by that period every frame.
- **Start-up code goes in a file's `init()`, not at its top level.** `js/main.js` calls the `init()`s in a fixed order. A module's top level may hold only function declarations, `let` declarations, and constants built from literals and other constants of the same file. That keeps load order irrelevant and lets the Node tools import modules without a page.
- **Every value has one owning file.** A module cannot assign to a variable it imports, so a value is set only by its own file: `export let` there, read by import elsewhere, changed from outside only through that file's functions. State that a frame changes in many places lives in five objects: `cam` (camera.js), `tr` (warp.js), `clock` (clock.js), `scene` (choose.js), `sel` (state.js). Do not add a catch-all shared object.
- **`frame()` in `js/loop.js` is a list of steps.** A new per-frame behaviour is a new step, or part of an existing one, in the file that owns what it changes. Steps hand values on through the frame's notes (`fr`); add a new field to the comment above it in `loop.js`.
- **A name in `__dbg` must not be used by another file's `__dbg`.** `main.js` merges them all into `window.MF`, so the later one hides the earlier and a test calls the wrong thing. `tools/unit.mjs` fails on a repeat.
- **Every file ends with `__dbg`**, a getter (and setter, if it changes) for each of its names; `main.js` merges them into `window.MF` (and offers the fields of the five state objects by bare name), which is how `tools/harness.py` and `--js` reach internals. A new name that a test or `--js` uses must be added to its file's `__dbg`. The harness asserts on the exact `<script type="module" src="js/main.js">` tag.
- **`tools/unit.mjs` and `tools/pack.mjs` import functions from the modules.** Those functions must stay free of the page: no `document`, no `gl`, none of the state objects.
- **A flight link, a room's code, what the meeting point says and every message from a friend are a stranger's text.** They go through `flUnpack` (`js/flightdata.js`), `tgRoom`, `tgSignal` and `tgClean` (`js/together.js`) and nowhere else. What comes out may only be numbers in a checked range and names that are compared with the app's own lists (`jApply`, a world's id): never shown as HTML, run, or used as an address. A new field needs its check there and a broken example in `tools/unit.mjs`.
- **Nothing a friend sends may move this user's camera unless this user has just agreed to it.** `tgGoTo` is the only place a message moves the camera, and only while `want` is set by this page's own button press. A request from a friend is shown (`ask`), never acted on.
- **The world beyond a doorway is drawn by the same `worldPass` and the same shader as the world in use**, and the two pictures must agree, or going through shows as a jump. Anything new that goes into the scene shader must be given to both passes alike, unless it lives in one world (the orb, sprites, friends), in which case it is left out of the pass that has `clip`. A doorway needs a JavaScript `de` at both ends (`doorWorld`); it is off in the VR viewer and over the land, where the second picture would need work that has not been done.
- **Inside out is a second answer from every world's distance, made in two places that must match**: `map` in `fragSource` (over the world's own `map0`) and `inDe` in `js/worlds.js` (over the world's own `de0`). They differ only inside the new walls, where the script answers 0 and the shader a negative number; keep that, since flight reads the size of a distance as open room. `tools/probe.py` compares them. A world's own distance is `de0` after start-up: code that wants the shapes themselves, not the swap, must call that. The shell must come from a fixed set of places, never chance ones, so that every device gets the same number.
- **The light shafts are in a world's program only while in use**, as chrome is: `shafts` is part of what `fragSource` returns and of the program set's name (`progSync`).
- **Photo mode's three numbers (`photoFov`, `photoExp`, `photoFocus`) are 1 outside it.** Anything new it changes must be so too, and must be in `photoKey()`, which Hold still compares.
- **What was playing (`media` in a scene) is a stranger's text when a picture or pack is loaded.** It goes through `cleanMedia` in `js/packs.js` and is then only shown as text (`toast`, `fillText`), used as numbers to move the page's own music, or made into a file name by `mediaSlug`, which lets through letters, digits and hyphens only. It must never reach the page as markup or an address. Nothing about the music may go into a file while `mediaShare` is off: read it only through `mediaNow()`.
- **The page sends nothing by itself.** `js/send.js` shares a file or opens Reddit only in answer to a press, and only with what the row shows.
- **A typed code is a stranger's text.** It goes through `cardCode` and then the address's hash, as a link does, and nowhere else. A postcard draws a world's or palette's name with `fillText` only.
- **A strange doorway's two sides differ by a turn `T` that leaves the ring's facing as it is** (`doorLieTurn`), and the camera's directions are turned by it on going through. A new kind must keep that, or the ring, its clip plane and `doorCross` are wrong. After a mirrored one the camera is left-handed (`cam.hand` is -1): anything that works out the camera's right from up and forward must call `camSquare()`, and anything that turns the camera about one of its own axes must multiply the angle by `cam.hand`, as `turn` does.
- **While a loop is flown (`lapOn()`, `js/lap.js`) the picture must be the same one lap later.** `lapClock` sets every clock and the sound from the lap's phase, and `frame()` skips `tickClock` and Journey. Anything new that changes the picture over time must take its time from `clock` or the sound from `fr` (then it comes round by itself), or be left out or stopped while `lapOn()`, as the orb, sprites, thrown light, friends, ribbons and doorways are. After a change that could matter, compare the picture one lap apart with frames of equal length; it should be identical.
- **Lens blur moves the ray's start and aim in the scene shader (`uLens`)**, and Hold still averages the frames. The world beyond a doorway is given the same lens scaled by the doorway's `s`. Anything drawn in the scene shader from `ro` and `rd` is blurred with the rest; anything drawn from the pixel's place alone is not, and will look wrong with it.
- **A guest's world and morph are the host's** (`togetherClock`), and a played flight's morph is the recording's (`flightClock`), because a place means the same thing only in the same shape. Anything new that moves geometry must come from the morph clock, or be sent and recorded too.
- **Packs never carry JavaScript.** Everything read from a pack, pasted text or `localStorage["mirrorfold-library"]` goes through `loadPack` and the cleaners. Do not add a field that is evaluated as script, used as HTML, or used as a URL. New numeric fields need a range in the cleaner and in `packs/README.md`.
- **The gallery is the `packs/` folder, and merging into it is the review.** `tools/offer.mjs` and `.github/workflows/offer.yml` turn an issue from a stranger into a pull request. Keep the issue as data: nothing from it may reach a shell command, a file path or a workflow expression except the issue number and the file name `slug()` makes.
- **A pack world has no JavaScript `de`.** Anything that needs a distance from `world` must work when `world.pack` is true: use `deMany` for many points and `packD` (filled by `packFrame`) inside `frame()`. `world.de` on a pack world is one probe, which makes the page wait for the graphics chip, so do not call it in a loop. Pack worlds are added and removed at run time after the built-ins (`NWORLD`); call `refreshLists()` afterwards.
- **Pack filter, overlay and world code is GLSL, checked by `cleanCode`.** World code has no clock and no sound either, and is folded into its period before it runs. Filter code has no clock: do not give it any input that changes with time or sound. Overlay code has the clock and the sound. Do not loosen a rule in `cleanCode` without reading why it is there (architecture doc, section 11, Packs). While any code that is not `reviewed` is in use, the flash limiter in pass 4 of `frame()` must be on. Only `loadPack(text, "site")` may mark code reviewed.
- **The editor writes through the cleaners.** A new slider needs a row in `ED` (with its help sentence, which the Help button shows), a range in the cleaner and a line in `packs/README.md`, all agreeing.
- **Palettes, motions, filters and overlays can be added and removed at run time.** Built-ins come first (`NPAL`, `NMOT`, `NLOOK`, `NOV`). Use `palOpen(i)` for whether a palette is usable, and call `refreshLists()` after changing either list.
- **Journey templates are keyed by option name**, not index (`"Melt"`, `"julia"`, `"6"`). Renaming a world id, motion, filter, overlay or palette silently drops it from users' saved templates.
- **Motion parameters are per frame at 60 fps** and are corrected for frame time where they are applied in `frame()`. Keep new ones consistent. A motion's drivers go through `driven()`, which holds the result inside `MOTION_LIM`; do not let `decay`, `kick` or any filter number be driven by the sound.
- **The VR viewer draws one picture per eye, and its effects work on the view from between the eyes.** Anything worked out on the screen shows each eye something different. In the viewer the trail and final passes bend the middle view and carry each piece's depth with it (`VR_GLSL` in `js/shaders.js`; architecture doc, section 13). A new effect that moves pixels must read the picture through `bend()` in `FS_TRAIL` or `at()` in `FS_FINAL`, never at `v` plus an offset that differs between the eyes; one that cannot (pack filter code) is switched off while `stereo` is true. The scene shader's fourth output number is depth in the viewer and 1 outside it: do not use it for anything else. The land shaders' is depth too when the land is alone, and when over a world 0 for no land and from 0.5 up for land with its depth; the number 0.064 in them must stay equal to `VR_EMAX`. The lens numbers `fr.vrOff` and `fr.vrTan` must be set every frame whatever is drawn, since the effect passes divide by them. After a change, compare `tools/stereo.py` on a render of the effect with a render of the plain picture.
- **Shaders read the video only through `tV` in `js/video.js`**, the copy whose brightness is rate-limited by `videoFrame`. Never bind the raw video texture in a drawing pass: a user's video may strobe. Ways of showing it that are flat on the screen are off in the VR viewer (`d3` in `VMODES`).
- **The zoom worlds are flat pictures, not spaces** (`flat: true`, drawn and moved by `js/zoom.js`). They are also `volume: true` so that code needing a surface skips them; anything new that needs a surface or a place in the world must skip `w.flat` or `w.volume`. The shader follows each pixel as a difference from a reference path worked out in doubles in JavaScript; do not try to pass the view's middle to the shader as a uniform, it has too few digits. What can be passed is how far the picture's middle is from the reference point in units of the view's size (`zm.ox`, `zm.oy`), which is how the picture is kept on its busy part without moving the reference. The Julia constant in use is `zm.jx + zm.wx`, not `zm.jx`: the sound pushes it. Nothing may write `cam.lookX` or `lookY` for a flat world unless the user did it: `stepZoom` treats any look as the user taking the picture. A tour target must be an exact point (the reference is the target's own path), so add one with its full double value, not a rounded one.
- **Programs are made in two halves** (`linkStart`, `linkEnd` in `js/programs.js`), and `js/preload.js` makes the land's and the worlds' ahead of need. Asking the chip anything about a program (`getProgramParameter`, `getShaderParameter`, `getUniformLocation`, a draw) makes the page wait until it is made, so nothing may touch `w.job` or `pLandJ` except through `build(w)`, `buildReady`, `landFinish` and `landReady`. Headless software rendering has no `KHR_parallel_shader_compile`, so `check.py` never runs this path: test a change to it on a real chip (`--use-angle=gl --enable-gpu`).
- **Every sampler in the scene shader must be given a texture unit every frame.** One left at the default, unit 0, can name the picture being drawn into, and the chip then refuses the draw.
- **Hold still averages frames of a scene that must not change.** While `stillN` is not zero the scene shader gets no sound and no clock runs. Anything new that changes the scene from frame to frame must either stop while `still` is true or be added to what `stillAim` compares.
- **User look input goes through `userLook(dx, dy)`**, not straight into `lookX`/`lookY`. That is how the autopilot knows to stand back while the user steers. The autopilot itself still writes `lookX`/`lookY` directly.
- **The dancers' joints are worked out in JavaScript (`js/dance.js`) and only drawn by the trails shader.** A move (`js/moves.js`) is a list of poses at given beats; a pose is 28 numbers that give hands and feet as places, sides measured outward, and `danceBody` makes a body in space from it with every bone keeping its length. A move with no `hold` flows through its keys without stopping; give it a `hold` only if it should stop on the beat. The knees' give comes from the bass itself (`st.kick`), not from the move. A new move must begin at beat 0, take 1, 2, 4, 8 or 16 beats, name its poses only by what differs from standing, and show from in front: a limb moved straight toward the viewer hardly shows, so send it to the side as well. Look at it as a row of poses before keeping it. A figure's pose is only ever gone toward (the end of the loop in `danceStep`), never set, a move is never changed while the last change is still crossing over, and elbows swing through `mem`: `tools/unit.mjs` holds every joint under seven figure heights a second. The figures stand on a floor that goes away from the viewer (`place`): nothing may come nearer than its front edge, and `danceFill` hands them to the shader furthest first, which draws each over the ones before. The shader's arrays and loop are written for `DN_MAX` (12) figures, 108 uniform vectors; change the three together. The figures dance only while the beat clock is `sure` of a steady beat; otherwise they wait or walk (`idle`), and anything new they do without a beat belongs there, turning no faster than `DN_TURN`. The moves are chosen by chance, so the figures stop under Hold still and are left out while `lapOn()`.
- **Nothing may strobe.** Pulses are soft and slow by design (tap tempo above about 165 BPM is halved). Respect `calm` (`prefers-reduced-motion`).

## Conventions

- Inside the files the style is still ES5: `var`, function declarations, no classes. Module syntax (`import`, `export`, `const`, `let`) is used only at the top level of a file.
- Shaders are arrays of strings joined with newlines. GLSL ES 1.00 only: constant loop bounds, no dynamic indexing of uniform arrays, float literals need a decimal point.
- Comments say what a block is for in plain words. Keep that.
- User-facing text is plain and literal: a control says exactly what it does.
- After any shader change run `python3 tools/check.py`, and render the affected world or effect and look at it. Several bugs in this project's history compiled cleanly and looked wrong.

## Verified and unverified

Everything was developed against headless Chrome with software rendering. Real-device frame rate, multi-touch gestures, how the audio sounds, and several iOS behaviours have never been tested by the author. The list is in the architecture doc, section 14. Treat user reports from a real phone as more reliable than the harness.
